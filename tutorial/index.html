Prototype workshop

Build a smart football

Start with a tap on the workbench. Get the sensors to agree on that touch, send the count to a phone, then explore how the electronics could survive inside a ball.

Set up the bench

Get the five main parts

Use a Seeed XIAO ESP32C3, a 3.3 V-compatible BMI160 breakout, a wired piezo disc, the protected TAC 500 mAh cell, and the DFRobot DFR0362 transmitter and receiver pair. The XIAO has a single-cell charge controller. Leave the cell and the coils aside for the first test.

See the NZ prototype budget

Gather tools and small parts

Use a breadboard, headers, jumper wire, multimeter, wire strippers, a soldering iron and solder. For mounting, gather flexible wire, insulating tape, heat-shrink and strain relief. A scope helps check short impact pulses.

For a bare piezo, set aside 1 MΩ and 100 kΩ resistors and two small-signal Schottky clamp diodes. If your IMU lacks pull-ups, add two 4.7 kΩ resistors. For charging, use a regulated 5 V supply sized for the transmitter, a separate power Schottky diode rated for the receiver current, and a mating lead for the protected battery.

Start with a removable test surface

Tape the piezo brass rim to a flexible test panel and secure the leads nearby. Fix the IMU firmly to the same panel. Hand taps should move both sensors together. Use a foam shell or an open, unpressurised model for the first fit check.

Prepare the computer and phone

On a computer, install Arduino IDE and the Espressif board package. Use a USB-C cable that carries data. On a Bluetooth Low Energy-capable phone, install nRF Connect for Mobile to view the first notifications. Arduino IDE · nRF Connect

Wire the sensors

Unplug USB while making connections. Attach the XIAO’s supplied antenna before the radio test. Read the labels on your particular BMI160 module. The following connections assume a breakout that accepts 3.3 V and exposes I²C.

XIAO pinConnection
3V3BMI160 3.3 V supply input. If the module exposes a separate VDDIO, follow its instructions for 3.3 V logic.
GNDBMI160 ground, piezo return and the signal circuit’s ground.
D4 / GPIO6BMI160 SDA. On a combined SPI/I²C header this may be marked SDI.
D5 / GPIO7BMI160 SCL, sometimes marked SCK. Keep both I²C pull-ups at 3.3 V. If the breakout has no pull-ups, add one 4.7 kΩ resistor from each line to 3V3.
D1 / A1 / GPIO3Conditioned piezo signal, after the series resistor and clamps described below.

If the module breaks out CSB and SDO without fixed straps, select I²C by tying CSB high to 3V3. SDO low selects address 0x68 and SDO high selects 0x69. Follow the module’s existing jumper settings. Seeed pin map · Bosch BMI160 datasheet

Protect the analogue input

A flexing piezo generates brief voltages of both polarities. For a bench circuit, connect the brass-side lead to ground, put 1 MΩ across the two piezo leads, then run the other lead through 100 kΩ to A1. At A1, place one Schottky diode with its anode at ground and striped cathode at A1. Place the other with its anode at A1 and striped cathode at 3V3. Adjust the impact fixture or attenuation if light taps saturate the ADC. Use gentle taps with the circuit powered and verify the clamped waveform before increasing force. SparkFun’s guide to piezo input conditioning

Read your first tap

In Arduino IDE install Espressif’s esp32 board package, select XIAO_ESP32C3 and its USB port, and enable USB CDC On Boot if the Tools menu offers it. Upload this bring-up sketch and open Serial Monitor at 115200 baud. It uses Arduino’s bundled Wire library. Keep the computer attached for this step. Seeed board setup

Download the Arduino sensor-check sketch (.ino). Open it in Arduino IDE and accept the offer to move it into a matching sketch folder if prompted.

Read the sketch in your browser 
#include <Arduino.h>
#include <Wire.h>

uint8_t imuAddress = 0;
int piezoPeak = 0;
uint32_t lastSample = 0;

bool readRegisters(uint8_t address, uint8_t reg, uint8_t *bytes, size_t count) {
  Wire.beginTransmission(address);
  Wire.write(reg);
  if (Wire.endTransmission(false) != 0) return false;
  if (Wire.requestFrom(address, count) != count) return false;
  for (size_t i = 0; i < count; ++i) bytes[i] = Wire.read();
  return true;
}

bool writeRegister(uint8_t reg, uint8_t value) {
  Wire.beginTransmission(imuAddress);
  Wire.write(reg);
  Wire.write(value);
  return Wire.endTransmission() == 0;
}

void stopWith(const char *message) {
  for (;;) {
    Serial.println(message);
    delay(2000);
  }
}

void setup() {
  Serial.begin(115200);
  delay(1000);
  Wire.begin(D4, D5);
  Wire.setClock(400000);
  for (uint8_t address = 0x68; address <= 0x69; ++address) {
    uint8_t id;
    if (readRegisters(address, 0x00, &id, 1) && id == 0xD1) {
      imuAddress = address;
      break;
    }
  }
  if (!imuAddress) stopWith("No BMI160 at 0x68 or 0x69. Check power and I2C.");
  if (!writeRegister(0x7E, 0x11)) stopWith("Accelerometer startup failed.");
  delay(10);
  if (!writeRegister(0x7E, 0x15)) stopWith("Gyroscope startup failed.");
  delay(100);
  // 100 Hz, normal filtering, +/-16 g and +/-2000 degrees/sec.
  if (!writeRegister(0x40, 0x28) || !writeRegister(0x41, 0x0C) ||
      !writeRegister(0x42, 0x28) || !writeRegister(0x43, 0x00)) {
    stopWith("Sensor configuration failed.");
  }
  Serial.println("ms,gx_raw,gy_raw,gz_raw,ax_raw,ay_raw,az_raw,piezo_peak");
}

void loop() {
  int reading = analogRead(A1);
  if (reading > piezoPeak) piezoPeak = reading;
  uint32_t now = millis();
  if (now - lastSample < 10) return;
  lastSample = now;
  uint8_t data[12];
  if (!readRegisters(imuAddress, 0x0C, data, sizeof(data))) {
    stopWith("IMU read failed. Check connections and reset.");
  }
  Serial.print(now);
  for (size_t i = 0; i < sizeof(data); i += 2) {
    int16_t axis = (int16_t)(data[i] | ((uint16_t)data[i + 1] << 8));
    Serial.print(',');
    Serial.print(axis);
  }
  Serial.print(',');
  Serial.println(piezoPeak);
  piezoPeak = 0;
}

What to look for. At rest, one accelerometer axis reads about ±2048 raw counts when vertical. Rotate the panel to move gravity onto a different axis. Turn it by hand and watch the gyro change, then settle. A gentle tap should produce a piezo peak alongside an acceleration change. If the piezo stays flat, inspect its mounting and diode orientation. At the configured ranges, divide acceleration by 2048 for g and angular speed by 16.4 for degrees per second. Bosch register map and scale factors

Turn taps into a count

  1. Label several short recordings. Capture quiet handling, ten separated taps, fast paired taps and a deliberate knock against a padded surface. Speak or film the reference count. Keep the same sensor mounting between recordings.
  2. Find one event per touch. Plot the piezo peak and acceleration magnitude, calculated as √(ax² + ay² + az²). Pick a piezo threshold above the quiet trace and look for an acceleration change close in time. Enter a held state after a match. Re-arm when the piezo falls below a lower threshold and the ringing has died away. Tune the timing against the fastest real pair of taps.
  3. Send a running total. First run Espressif’s BLE Notify example and subscribe from nRF Connect on a phone. In your counting sketch, publish a read/notify characteristic containing the total as a 32-bit unsigned integer. Choose and record a service UUID, characteristic UUID and byte order for both ends. Set the value after each accepted event, advertise again on disconnect, and have the phone read the latest total after reconnecting. Espressif Notify example · nRF Connect for Mobile
  4. Build the app around a session. Display the latest total, save each finished session with its date, and derive personal bests from saved sessions. Use an explicit end button until recorded trials can distinguish a foot touch from a ground bounce. A shared leaderboard needs an online score store and a session ID to avoid duplicate submissions. A web version can subscribe via Web Bluetooth on supporting browsers over HTTPS. Check browser support on the target phone before choosing the web route. Chrome Web Bluetooth guide

Check the result. Use a fresh recording after tuning. Count missed touches and extra detections separately. A missed tap and a double count can cancel each other out in the final total. Disconnect the phone for several taps, reconnect, and check that the displayed total catches up.

Add battery and charging

  1. Check the cell. Use a protected 3.7 V nominal, 4.2 V full-charge pack. The specified TAC pack allows 500 mA maximum charge current. The XIAO’s listed fast-charge current is 380 mA. Inspect the cell, disconnect all power and verify connector polarity with a meter before attaching a mating lead to the XIAO BAT+ and BAT− pads. Solder the empty lead on the board first. Connect the cell afterwards. TAC battery and datasheet · Seeed battery wiring
  2. Test battery power. Verify counting over BLE on USB, unplug USB and repeat with only the battery connected. Use the phone to confirm that the board stays on. The XIAO’s indicator behaviour changes on battery power.
  3. Prove the inductive link separately. Supply the DFR0362 transmitter with regulated 5 V. With the receiver unattached to the electronics, align the coils and check receiver output and polarity with a meter. The product specifies 5 V output and a 2–10 mm operating gap. Repeat through a sample of the planned shell and mounting material. DFRobot coil pair specifications
  4. Feed the board’s charger. Follow Seeed’s external 5V-input guidance. Route receiver positive through a suitably rated low-drop Schottky diode, anode at receiver positive and cathode at XIAO 5V, and connect receiver ground to GND. Keep the battery on the BAT pads. Use only the inductive input during this charging test, with the USB cable unplugged. Confirm stable voltage at the board under load, charging indication and temperature in the open fixture. Seeed power pin guidance

Where it fits in a ball

The IMU measures motion wherever it is attached. A central mount reduces the extra acceleration created by an off-centre sensor during spin. The piezo needs a surface that flexes on contact, while the short-range charging coil needs to face the dock near the shell.

First fit in a foam model

Use a split foam model with a removable core. Start with dummy masses matching the boards and cell. Weigh it, roll it in different directions, and check whether one side repeatedly settles at the bottom. Leave space for wiring, strain relief and access to the module. A foam model can establish fit and balance before anyone kicks a prototype.

Playable-ball development

Work with a ball maker on a purpose-built bladder and centred carrier. A flexible connection can lead to the shell sensor and charging coil. Inspect the carrier, strain relief and cell enclosure after controlled impact tests with dummy electronics. A commercial precedent is adidas’s suspended central sensor in Al Rihla. adidas connected-ball design

When does the hardware go in?

  1. For a tabletop model, start with two foam halves. Mark the centre on the flat faces, make a recess for a removable dummy pod, and cut shallow channels for the leads. Seat the dummy coil beneath one face and mark the matching dock position on the outside. Close the halves with a removable fabric wrap so you can reopen and adjust them.
  2. For an inflatable football, build the access into the design. The inflation valve is sized for a pump needle. A ball maker would need to fit the carrier during bladder assembly, route and seal any connections through the pressure boundary, and install the near-surface parts before the outer panels are closed. Leak-test the bladder and check wireless coupling through the actual cover before final bonding. SELECT’s guide to football construction

Before play. An ordinary inflated ball has no service opening for this hardware. Keep it intact. The cell maker cautions against mechanical abuse. Only move from a bench model to a powered impact prototype after the enclosure, retention, balance, pressure integrity and charging temperature have been evaluated for repeated football impacts.
